| P12 | Secret vault backend: OS keychain / secret-service with an encrypted-vault fallback, and a single credential resolver | The app can **accept, store, rotate, and clear** a secret value (API key, provider token) without that value ever being written to `settings.toml`, an IPC response, a log, a diagnostic, or an export; `SecretReference::Keychain { id }` becomes writable from within the app instead of requiring the user to pre-provision the OS keychain by hand. Health/auth is presence-only, same hygiene as P3/P4. | 💤 **Later — not scheduled.** Deliberately deferred until (a) the app has its *own* direct model-call path — the planned "agents invoke specialised mini-models as swarm sub-orchestrators" capability (`communication.md` C16) is the trigger use case, distinct from driving CLI harnesses — and (b) the P3/P4/P12 provider + credential + health surface is mature. **Not** a substitute for a harness's own model picker (Cursor CLI, OpenCode): those own the agent loop and bill through their own product; this is harness-agnostic transport that sits *below* a harness and *above* hand-written orchestration code, and its payoff is collapsing N provider SDKs to one client plus one normalized cost figure for cost-per-task benchmarking. Builds on P4 (direct HTTP providers) and P12 (the gateway key is one more vault entry in the single resolver). OpenRouter and Requesty are the same category; pick at implementation time. |
| P14 | **MCP client**: human-launched MCP tool executions from the app | A human dev can pick an enabled MCP server, choose one of its tools, fill an argument form, run it, and read the result — without going through an agent turn. Requires CA to speak MCP as a **client** for the first time: today `hub::mcp` only *renders config* (`entry_for` → `apply_to_workspace`) so each harness can reach a server; nothing in the app ever performs `initialize` / `tools/list` / `tools/call` itself. Perplexity is the proof-of-concept. | 📋 **Not started — scheduled after the Mistral Vibe batch and the Moonshot swarm harness.** Delivery ladder, decided 2026-09-09: **(A) direct invoke-and-show** — the only slice currently in scope; **(C)** the same call recorded as a tracked Hub task so its result lands in the transcript and stays addressable by agents; **(B)** a model-driven loop over the server's toolset, which is `communication.md` **C16** with an MCP toolset and must not precede it. Two properties make A small: `McpServerEntry` already carries command + args + env and `enabled_keys` already tracks per-workspace enablement, so the client drives existing registry entries with **no new config surface**; and `tools/list` returns a JSON Schema per tool, so the argument form is **generated**, not hand-written per tool — one form covers Perplexity, the creative-tool bridges, and anything added later. Prior art for the transport is `commands/quota/codex.rs` (stdio JSON-RPC on a dedicated reader thread, `recv_timeout`, kill-on-timeout) and `crates/mcp/core` for framing. Token-free by construction — the same "let a human check something without spending an agent turn" motive as `orchestration.allow_metered_quota_probes`. Sits beside P9, which is the *server-config* half of MCP. |
