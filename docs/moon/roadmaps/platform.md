# Platform, Providers, Tools, and Security Roadmap

This capability roadmap contains the later daemon/API work and the near-term
reliability work needed by the hub.

| --- | --- | --- | --- |

| P3 | Provider adapters for Claude, Codex, Gemini, Grok, OpenCode, Ollama, and llama.cpp | Start/message/cancel/status/usage capabilities are typed; local models work offline | 🚧 **Partial** · Process discovery and quota adapters exist (`src-tauri/src/commands/quota/*` — Claude, Codex, Gemini, Grok, OpenCode, DeepSeek balance, plus `unavailable` rows for local/unmetered). Orchestrate can select **DeepSeek via OpenCode** (`opencode models` / `opencode run -m deepseek/<model>`) and **Mistral via vibe** (explicit `-p/--workdir/--trust/--output`, unavailable when missing or unauthenticated). C12 supplies safe capture/refusal plus Grok and conditional Codex delivery. C14 now owns native managed-session lifecycle, Claude Channel integration, a serialized Codex writer broker, and app-owned Antigravity (`agy`) workers. **Landed 2026-09-08:** Meta **Muse Code** (`communication.md` C14.11, #273) and **Cursor `agent`** (C14.12, #275 — held on review) managed harnesses; `HarnessId::{Muse,Cursor}` scaffold + roster identities #271. **In flight (2026-09-08 credentials batch, parent [#279](https://github.com/ACFHarbinger/Coding-Assistants/issues/279)):** quota adapters for the two new surfaces — Muse Spark via the Meta Model API ([#280](https://github.com/ACFHarbinger/Coding-Assistants/issues/280), still spike-gated) and the Cursor `agent` plan ([#281](https://github.com/ACFHarbinger/Coding-Assistants/issues/281), **ready for review** — dashboard `GetCurrentPeriodUsage` JSON via the CLI login token; no `~/.cursor` scrape). An `unavailable` row with an actionable `detail` string remains the landing state when the surface has no machine-readable usage or the user is not logged in. All quota adapters currently read their key straight from `std::env::var`; #287 migrates them onto the P12 unified credential resolver (vault → env). **Batch 2026-09-08 (parent [#291](https://github.com/ACFHarbinger/Coding-Assistants/issues/291)) — "complete the status surface":** the `usage` half is done; the `status` half is not. The only per-provider signals today are the heavy quota fetch (up to 25s for `agy`) or raw process discovery, so several readiness-panel rows (notably **Claude Code** and **Gemini `agy`**) show only "is the process running". Adds a typed, cheap `ProviderHealth` probe (`src-tauri/src/commands/health/*`, parallel to `quota/*`) — `installed` / `authenticated` / `auth_expires_at` / optional `endpoint_reachable`, no usage call, no long-timeout network by default; aggregate `hub_get_provider_health` / `hub_refresh_provider_health(agent_id)` ([#291](https://github.com/ACFHarbinger/Coding-Assistants/issues/291), Claude) surfaced in the readiness panel + Usage strip ([#292](https://github.com/ACFHarbinger/Coding-Assistants/issues/292), Gemini). Separately, managed-session liveness for the new **Muse**/**Cursor** harnesses is reconciled against `hub::proc` and the writer lease is surfaced ([#293](https://github.com/ACFHarbinger/Coding-Assistants/issues/293), OpenCode). Muse + Cursor add their own health branches by self-integration ([#294](https://github.com/ACFHarbinger/Coding-Assistants/issues/294)). Same secret hygiene as the quota adapters — only presence / expiry / reachability cross IPC. |

Ableton) creative-tool bridges. **#272 landed** (shared `hub::mcp::external` registry). **#276/#277 ready for review** — official **`@perplexity-ai/mcp-server`** (`npx -y`, `PERPLEXITY_API_KEY` from the client shell, never stored) and subscription **`perplexity-web-mcp-cli`** (`pwm-mcp`, `pwm login`, ~30-day quota-limited session, token-file presence only). Settings toggle remains #278 (Gemini). |

| P12 | Secret vault backend: OS keychain / secret-service with an encrypted-vault fallback, and a single credential resolver | The app can **accept, store, rotate, and clear** a secret value (API key, provider token) without that value ever being written to `settings.toml`, an IPC response, a log, a diagnostic, or an export; `SecretReference::Keychain { id }` becomes writable from within the app instead of requiring the user to pre-provision the OS keychain by hand. One resolver (`hub` crate) is the only place that reads a credential: **vault entry wins, `std::env::var` is the fallback**, and every provider/quota/harness adapter calls the resolver rather than `env::var` directly. Presence, source (`Keychain` / `Env Var $NAME` / `Provider Login`), and last-updated are the only credential facts that cross IPC. | 📋 **In progress** (2026-09-08 credentials batch, parent [#279](https://github.com/ACFHarbinger/Coding-Assistants/issues/279)). This is the "later modular platform decision" named in `settings.md` §"Persistence, scope, and security" — now scheduled. Backend + resolver only; the Settings surface that drives it is `settings.md` S8 (#283/#284). Split into: **[#282](https://github.com/ACFHarbinger/Coding-Assistants/issues/282)** (Claude) — the `SecretBackend` trait seam, the OS-keychain implementor via the `keyring` crate (Windows Credential Manager / macOS Keychain / Linux Secret Service), the `SecretString` wrapper (reuses already-vendored `secrecy`/`zeroize`), a writable `SecretReference::Keychain`, and the resolver; and **[#289](https://github.com/ACFHarbinger/Coding-Assistants/issues/289)** (Gemini) — a second `SecretBackend` implementor, an encrypted-file vault under `CA_HOME` using the already-vendored `ring` (ChaCha20-Poly1305 + PBKDF2, **no new dependency**), selected when no OS secret service answers. `#282` depends on nothing and unblocks #283/#284/#287; `#289` depends on #282's trait. |
