## 1. Version contract (fixed input for all delegates — do not re-invent)

- **`package.json` `version` is canonical.**
- `src-tauri/tauri.conf.json` → `"version": "../package.json"` (Tauri reads it from there;
  removes one of the three copies).
- `src-tauri/Cargo.toml` `version` and `android/app/build.gradle.kts` `versionName` are
  **written by `just release::bump <semver>`**, never hand-edited.
- Android `versionCode` is derived monotonically: `major*10000 + minor*100 + patch`
  (must be an integer; `1.0.0` → `10000`).
- v1.0 bump: `0.1.0` → `1.0.0` (done as the final step, after the pipeline is proven on a
  `0.1.x` dry-run tag).

4. `bundle.targets`: `"all"` → `["deb", "appimage", "msi", "nsis"]` (platform-inapplicable

7. Icons already present (`icon.ico`, `icon.icns`, `32/128/128@2x`, Square*Logo) — no

## 3. Workstream B — `tools/release/justfile`  *(owner: Codex/Chat)*

New sub-module `tools/release/justfile`, `mod release "tools/release/justfile"` in root
justfile, root shorthands as needed. Recipes:

- `bump <semver>` — write `package.json`, `src-tauri/Cargo.toml`, `android/app/build.gradle.kts`
  (`versionName` + derived `versionCode`); run `cargo update -p tauri-app --precise` /
  `npm i --package-lock-only` so lockfiles follow; print a diff; do **not** commit.
- `bundle-linux` — `npm run tauri build -- --bundles deb,appimage`
  (reuses the pinned local `@tauri-apps/cli`; `beforeBuildCommand` already runs
  `npm run build`, so **do not** depend on `build::frontend` — avoids a double frontend build).
- `bundle-windows` — `npm run tauri build -- --bundles msi,nsis` (runs on Windows only).
- `bundle-android` — `cd android && ./gradlew assembleRelease bundleRelease`
  (unsigned until Workstream C lands the `signingConfig`).
- `artifacts` — collect `target/release/bundle/**` + `android/app/build/outputs/**`
  into `dist/release/` with predictable names.
- `release <semver>` — orchestrator: `bump` → build all locally-buildable targets →
  `artifacts` → print the `git tag` / push instructions (tag push is manual, it triggers CI).

Constraints: bundle output is under **repo-root `target/`**, not `src-tauri/target/`.
Every recipe `[no-cd]` + `set working-directory` consistent with the other sub-modules.

## 4. Workstream C — Android companion release build  *(owner: Gemini/Agy)*

1. **Identity rename** (fixed input, do not choose):
   `com.example.remotelauncher` → **`com.codingassistants.remotelauncher`**
   in `android/app/build.gradle.kts` (`namespace`, `applicationId`), the Kotlin package
   directory tree under `android/app/src/main/java/...`, every `package`/`import` line, and
   `AndroidManifest.xml`. `ktlintCheck` + `./gradlew test` must stay green.
2. **Release keystore**: generate `android/keystore/release.jks` (RSA 2048, 10000-day
   validity), print the keystore + key passwords and alias to stdout **once** for Harbinger
   to store; add `android/keystore/` and `*.jks` to `.gitignore`; document the four values
   as CI secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
   `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
3. **`signingConfigs`**: add a `release` signing config reading from
   `keystore.properties` (git-ignored, local) **or** the `ANDROID_*` env vars (CI); wire
   `buildTypes.release.signingConfig`. `assembleRelease` → signed APK, `bundleRelease` →
   signed AAB.
4. `versionName` / `versionCode` come from the Workstream-1 contract — reference it, do
   not hard-code beyond the current `1.0` / `10000`.
5. A `just build::android-release` or fold into `tools/release` `bundle-android`
   (coordinate with Codex's Workstream B).

## 5. Workstream D — CI release workflow  *(owner: Claude)*

`.github/workflows/release.yml`:

- Trigger: `push: tags: ['v*']` + `workflow_dispatch` (with a `dry_run` input that skips
  the Release publish).
- `permissions: contents: write`.
- **Job `desktop`** — matrix:
  - `ubuntu-22.04` (⚠️ **not** `ubuntu-latest`/24.04 — a 24.04 AppImage requires glibc 2.39
    and won't run on older distros), installs
    `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf` + the rest of the
    Tauri Linux deps → `deb,appimage`.
  - `windows-latest` → `msi,nsis`.
  - Uses `tauri-apps/tauri-action@v0` with `projectPath: src-tauri` (or
    `tauriScript: 'npm run tauri'`) because of the non-default workspace layout; `args:
    '--bundles <per-OS>'`; `tagName`/`releaseName` from the pushed tag; creates a **draft**
    GitHub Release and uploads the bundles.
- **Job `android`** — `ubuntu-22.04`, `temurin` JDK 21, `android-actions/setup-android`,
  decode `ANDROID_KEYSTORE_BASE64` → `android/keystore/release.jks`, write
  `keystore.properties` from secrets, `./gradlew assembleRelease bundleRelease`, attach the
  signed APK + AAB to the same draft Release.
- **Do not** gate the release build on `cargo clippy -D warnings` (the current CI's red
  gate) — the release job builds bundles, it does not re-lint.
- `.gitea/` + `.forgejo/` copies: **skipped for v1.0** (no wired remote, and `windows-latest`
  has no self-hosted runner). Revisit if those forges get runners.
